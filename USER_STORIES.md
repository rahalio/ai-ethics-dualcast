# Dualcast — User stories

**Product:** [PRODUCT.md](./PRODUCT.md)


### Capability owner / research lead

- As a research lead, I want to register a capability artefact and see which security domains it touches before I submit a paper or ship an API, so that dual-use is a design input rather than a last-minute surprise.
- As a research lead, I want the assessment to force an expansion / new-threat / character-change classification, so that I cannot wave away misuse with a generic “benefits outweigh risks” paragraph.
- As a research lead, I want a time-boxed delayed-disclosure option with a clear reopen date, so that holds feel like responsible timing rather than indefinite censorship.

### Red-team / AI security researcher

- As a red-team lead, I want to run campaigns against a candidate release and attach findings to the gate, so that remediation is a release blocker rather than a post-mortem.
- As a security researcher, I want confidential intake for AI vulnerabilities with a disclosure clock, so that I can report adversarial exploits without dumping recipes into the open before patches or mitigations exist.
- As a red-team lead, I want findings tagged to digital, physical, or political security, so that mitigations match the domain the report cares about.

### Release / publication manager

- As a release manager, I want the gate to block API exposure until openness regime and red-team status clear, so that product and research channels cannot bypass each other.
- As a release manager, I want central-access versus full-open as selectable regimes with different technical controls, so that capability can be offered as a service without handing attackers the weights and recipes.

### Policy and external engagement

- As a policy lead, I want outreach tasks created when foreseeability thresholds trip, so that Recommendation #2’s “proactively reach out” is tracked work rather than aspiration.
- As a policy lead, I want stakeholder reviewers assigned for high political-security scores, so that Recommendation #4’s expanded circle is enforced.

### Compliance, board, and whistleblower

- As a compliance officer, I want an assurance pack that shows taxonomy scores, openness rationale, and residual risk acceptances for a release cohort, so that the board can evidence dual-use process.
- As a whistleblower, I want a confidential channel that routes misuse concerns to an independent intake role, so that culture-of-responsibility claims have a real exception path.
- As a board member, I want visibility into delayed and selective-sharing inventories, so that reduced openness remains transparent and challengeable.
